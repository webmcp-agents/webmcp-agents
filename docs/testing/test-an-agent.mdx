An agent's behavior depends on a model, which is slow, costs money and answers differently each time. To test your side
of it (the tools are there, they run in order, the agent sees only the tools it should), replace the model with a
script. `mockAdapter` plays the script as if a model had sent it: a tool call, then another, then text.

`storeAgent.invoke` runs the real loop: each scripted tool call goes through `document.modelContext` to the tool on the
page, and its result goes back to the "model". Only the model's choices are fixed.

## What to check

- `toHaveCalledTools([...])`: exactly these tools, in this order. `toHaveCalledTool(name, input?)` for one of them.
- `toHaveAnswered(text)`: the final text.
- `toHaveFinishedWith("stop")`: how the run ended (`"max-steps"`, `"aborted"`, `"error"`).
- `toHaveBeenOfferedTools(...)` on the adapter: what the model was shown. Use it to check an agent's `tools` subset,
  or that a tool on another page was not offered.

The `runs` fixture records the run events of every run in the test ([`onAgentRun`](/reference/chat/on-agent-run)),
and the same matchers read it, which helps when the run is started by the chat rather than by your test.

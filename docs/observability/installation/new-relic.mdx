## Install the packages

The telemetry layer and its OpenTelemetry packages, plus the protobuf exporter: New Relic recommends HTTP/protobuf and does not say JSON is accepted.

```package-install
npm install @webmcp-agents/telemetry @opentelemetry/api @opentelemetry/sdk-trace @ai-sdk/otel @opentelemetry/exporter-trace-otlp-proto
```

## Set the environment

<include lang="bash" meta='title=".env"'>/_examples/observability/env/new-relic.env</include>

- **Endpoint:** `https://otlp.nr-data.net` (US), `https://otlp.eu01.nr-data.net` (EU), `https://otlp.jp.nr-data.net` (JP), `https://gov-otlp.nr-data.net` (FedRAMP); ports 443, 4317 and 4318.
- **Auth:** `api-key: <license key>`.

## Add the relay route

The page's spans come to your own endpoint, so the backend's key never reaches the browser. The relay refuses other origins and requests with no `Origin` (a script, not a page); the `guard` is the per-IP limit for the rest. Keep its counts in a shared store in production, as for the chat ([Limits and budgets](/security/limits)).

## Check it in New Relic

Start the app and send one message in the chat. The trace appears in New Relic.

:::note[New Relic's limits]
1 MB per payload; attribute values up to 4095 characters, at most 128 attributes per span. With `recordInputs` or `recordOutputs` on, long prompts and answers are cut at 4095 characters.
:::

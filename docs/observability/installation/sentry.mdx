## Install the packages

The telemetry layer and its OpenTelemetry packages, beside the Sentry SDK your server already has. `@opentelemetry/sdk-trace` is not needed when the app registers a tracer provider, as Sentry does.

```package-install
npm install @webmcp-agents/telemetry @opentelemetry/api @opentelemetry/sdk-trace @ai-sdk/otel
```

## Add the server layer

If your server already initializes Sentry, add one option. `enableOpenTelemetrySetup: true` makes Sentry register its OpenTelemetry provider, which the layer then finds and uses ([rule 3](/observability/where-spans-go)). Without it, most of Sentry's server SDKs register none, and the layer stays off. `@sentry/nextjs` and `@sentry/sveltekit` turn it on by default.

Sentry never replaces a provider that is already registered: if your app has one, follow Sentry's custom setup instead (its OTLP endpoint in your provider), and the layer uses your provider.
:::

## Add the relay route

The page's spans come to your own endpoint, so the backend's key never reaches the browser. The relay refuses other origins and requests with no `Origin` (a script, not a page); the `guard` is the per-IP limit for the rest. Keep its counts in a shared store in production, as for the chat ([Limits and budgets](/security/limits)).

## Check it in Sentry

Start the app and send one message in the chat. Sentry groups AI spans into conversations by `gen_ai.conversation.id`, which the layer maps; set the person with `Sentry.setUser`. Sentry's own instrumentations, such as its `vercelAIIntegration`, are Sentry's to configure ([Privacy and redaction](/observability/privacy)).

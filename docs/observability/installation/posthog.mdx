## Install the packages

The telemetry layer and its OpenTelemetry packages. PostHog accepts OTLP over HTTP as JSON or protobuf, so the built-in exporter needs nothing more.

```package-install
npm install @webmcp-agents/telemetry @opentelemetry/api @opentelemetry/sdk-trace @ai-sdk/otel
```

## Set the environment

PostHog's path does not end in `/v1/traces`: set the exact URL with the `…_TRACES_ENDPOINT` variable. The base variable would append `/v1/traces` and get a `404`.

## Add the relay route

The page's spans come to your own endpoint, so the backend's key never reaches the browser. The relay refuses other origins and requests with no `Origin` (a script, not a page); the `guard` is the per-IP limit for the rest. Keep its counts in a shared store in production, as for the chat ([Limits and budgets](/security/limits)).

## Check it in PostHog

Start the app and send one message in the chat. PostHog keeps only spans whose name or attributes start with `gen_ai.`, `llm.`, `ai.` or `traceloop.`; this library's spans carry `gen_ai.*`, so they pass, and with the default `conventions: "genai"` model spans become `$ai_generation` events. PostHog takes its session from `$ai_session_id`, or else from `gen_ai.conversation.id`, which the layer maps. The person is `posthog.distinct_id` (or `user.id`): set it from your own user id where you have one.

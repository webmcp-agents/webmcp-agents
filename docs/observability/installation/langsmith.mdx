<div class="install-steps">

## Install the packages

The telemetry layer and its OpenTelemetry packages, plus the protobuf exporter: LangSmith's docs do not say whether OTLP JSON is accepted, and every example of theirs, their own JS exporter included, uses protobuf.

```package-install
npm install @webmcp-agents/telemetry @opentelemetry/api @opentelemetry/sdk-trace @ai-sdk/otel @opentelemetry/exporter-trace-otlp-proto
```

## Set the environment

LangSmith takes OTLP at `/otel` under its API host; the exporter appends `/v1/traces`.

<include lang="bash" meta='title=".env"'>/_examples/observability/env/langsmith.env</include>

- **Endpoint:** `https://api.smith.langchain.com/otel` (US). EU `https://eu.api.smith.langchain.com/otel`, APAC `apac.`, AWS `aws.`; self-hosted `https://<host>/api/v1/otel`.
- **Auth:** `x-api-key: <LANGSMITH_API_KEY>`.
- **Project:** `Langsmith-Project: <name>` (the legacy form), or the newer `Langsmith-Agent-Id` with `Langsmith-Agent-Environment`.

:::warning[One project form]
Send `Langsmith-Agent-Id` and `Langsmith-Agent-Environment` together or not at all, and never with `Langsmith-Project`: that request is refused with `400`.
:::

## Add the server layer

The endpoint, headers and protocol come from the environment; the layer adds the key LangSmith groups threads by. The default `conventions: "genai"` fits: LangSmith maps `gen_ai.*` attributes (model, token counts, messages).

<include meta='title="lib/observability.ts"'>/_examples/observability/backends/langsmith.ts</include>

## Add the relay route

The page's spans come to your own endpoint, so the backend's key never reaches the browser. The relay refuses other origins and requests with no `Origin` (a script, not a page); the `guard` is the per-IP limit for the rest. Keep its counts in a shared store in production, as for the chat ([Limits and budgets](/security/limits)).

Start the app and send one message in the chat. The trace appears in the project, grouped into a thread by `langsmith.trace.session_id`.

Six steps, from the packages to one trace per turn in Langfuse: the same six on every backend's page. The framework
picker above the code picks your routes; the backend stays picked for the pages after this one.

<div class="install-steps">

## Install the packages

The telemetry layer and its OpenTelemetry packages, plus Langfuse's span processor.

```package-install
npm install @webmcp-agents/telemetry @opentelemetry/api @opentelemetry/sdk-trace @ai-sdk/otel @langfuse/otel
```

## Set the environment

The processor reads `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` and `LANGFUSE_BASE_URL` (version 6 no longer reads `LANGFUSE_HOST`):

<include lang="bash" meta='title=".env"'>/_examples/observability/env/langfuse.env</include>

Regions: EU `https://cloud.langfuse.com`, US `https://us.cloud.langfuse.com`, Japan `https://jp.cloud.langfuse.com`, HIPAA `https://hipaa.cloud.langfuse.com`, or your own host.

## Add the server layer

Langfuse's span processor, and the key Langfuse groups sessions by. The processor exports only spans that carry a `gen_ai.*` attribute or come from a known instrumentation; every span of this library carries `gen_ai.operation.name`, so all of them pass.

## Add the relay route

The page's spans come to your own endpoint, so the backend's key never reaches the browser. The relay refuses other origins and requests with no `Origin` (a script, not a page); the `guard` is the per-IP limit for the rest. Keep its counts in a shared store in production, as for the chat ([Limits and budgets](/security/limits)).

## Check it in Langfuse

Start the app and send one message in the chat. The trace appears in Langfuse, in a session keyed by `langfuse.session.id` (or `session.id`); people go by `langfuse.user.id` (or `user.id`).

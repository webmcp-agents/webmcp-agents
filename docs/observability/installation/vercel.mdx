## Install the packages

The telemetry layer and its OpenTelemetry packages, plus Vercel's. `@opentelemetry/sdk-trace` is not needed when the app registers a tracer provider, as `@vercel/otel` does.

```package-install
npm install @webmcp-agents/telemetry @opentelemetry/api @opentelemetry/sdk-trace @ai-sdk/otel @vercel/otel
```

## Set the environment

Nothing new for the layer. `@vercel/otel` reads the `OTEL_EXPORTER_OTLP_*` variables for its own exporter, but its default protocol is `http/protobuf` (the layer's own is `http/json`), and it has no gRPC. Its `traceExporter` and `spanProcessors` options take an instance, such as its `OTLPHttpJsonTraceExporter`.

## Add the relay route

The page's spans come to your own endpoint, so the backend's key never reaches the browser. The relay refuses other origins and requests with no `Origin` (a script, not a page); the `guard` is the per-IP limit for the rest. Keep its counts in a shared store in production, as for the chat ([Limits and budgets](/security/limits)).

## Check it in Vercel

Start the app and send one message in the chat. Vercel's Trace Drains forward the traces to a backend of your choice, as OTLP over HTTP; they need `@vercel/otel` (a hand-written SDK setup gets no drains). On Vercel without `@vercel/otel`, the [`createVercelTelemetryRoute`](/reference/vercel-api/create-vercel-telemetry-route) and the `OTEL_*` variables are enough: the handler hands its export to Vercel's `waitUntil`.

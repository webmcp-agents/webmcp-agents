<div class="install-steps">

## Install the packages

The telemetry layer and its OpenTelemetry packages, plus LangWatch's package, whose `LangWatchExporter` (from `langwatch/observability`, an alias of `LangWatchTraceExporter`) sends protobuf.

```package-install
npm install @webmcp-agents/telemetry @opentelemetry/api @opentelemetry/sdk-trace @ai-sdk/otel langwatch
```

## Set the environment

<include lang="bash" meta='title=".env"'>/_examples/observability/env/langwatch.env</include>

- `LANGWATCH_ENDPOINT` for a self-hosted instance (default `https://app.langwatch.ai`).
- `LANGWATCH_PROJECT_ID` for user-scoped keys.
- The exporter also takes these as options: `apiKey`, `endpoint`, `projectId`, `filters`.

<Expandable title="Without the package">

OTLP to `https://app.langwatch.ai/api/otel/v1/traces` with `Authorization: Bearer <LANGWATCH_API_KEY>`. JSON and protobuf are both accepted; gRPC is not.

</Expandable>

## Add the relay route

The page's spans come to your own endpoint, so the backend's key never reaches the browser. The relay refuses other origins and requests with no `Origin` (a script, not a page); the `guard` is the per-IP limit for the rest. Keep its counts in a shared store in production, as for the chat ([Limits and budgets](/security/limits)).

## Check it in LangWatch

Start the app and send one message in the chat. The trace appears in LangWatch, grouped into a thread by `langwatch.thread.id` (people by `langwatch.user.id`). The exporter drops HTTP request spans by default (`filters`); the agent's spans are not affected.

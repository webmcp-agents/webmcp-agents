## Install the packages

The telemetry layer and its OpenTelemetry packages. Datadog's agentless intake takes OTLP over HTTP as JSON or protobuf (not gRPC), so the built-in JSON exporter needs nothing more.

```package-install
npm install @webmcp-agents/telemetry @opentelemetry/api @opentelemetry/sdk-trace @ai-sdk/otel
```

## Set the environment

<include lang="bash" meta='title=".env"'>/_examples/observability/env/datadog.env</include>

- **Endpoint:** `https://otlp.<site>/v1/traces`, for the sites `otlp.datadoghq.com`, `otlp.datadoghq.eu`, `otlp.us5.datadoghq.com` and `otlp.ddog-gov.com`.
- **Headers:** `dd-api-key: <key>`. `compute_stats=true` computes trace metrics, which the direct intake does not do by default.
- **A Datadog Agent** receives OTLP on 4317 and 4318: point `OTEL_EXPORTER_OTLP_ENDPOINT` at it instead, and the Agent holds the key.

:::warning[LLM Observability needs one attribute]
LLM Observability reads only traces with the resource attribute `dd_llmobs_enabled=true` (or the header `DD-LLMObs-Enabled: true`), as the file above sets. It reads `gen_ai.*` and drops spans without it.
:::

## Add the relay route

The page's spans come to your own endpoint, so the backend's key never reaches the browser. The relay refuses other origins and requests with no `Origin` (a script, not a page); the `guard` is the per-IP limit for the rest. Keep its counts in a shared store in production, as for the chat ([Limits and budgets](/security/limits)).

## Check it in Datadog

Start the app and send one message in the chat. The trace appears in APM and, with `dd_llmobs_enabled=true`, in LLM Observability, which builds sessions from `gen_ai.conversation.id`. A `403` from the intake means its host does not match your site.

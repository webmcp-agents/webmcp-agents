<div class="install-steps">

## Install the packages

Helicone is not an OpenTelemetry backend: it has no general OTLP endpoint. It sits between your server and the model provider and logs every call that passes through it, so it is set up as the chat's model. Its provider package:

```package-install
npm install @helicone/ai-sdk-provider
```

## Set the environment

Your Helicone key, on the server. Your provider keys are kept in Helicone's dashboard.

```bash .env
HELICONE_API_KEY=…
```

## Add the server layer

Give the chat handler a Helicone model, in place of the model it had:

<include meta='title="api/chat.ts"'>/_examples/observability/backends/helicone.ts</include>

The older proxy form (`createOpenAI({ baseURL: "https://oai.helicone.ai/v1", headers: { "Helicone-Auth": … } })` with `Helicone-Session-Id` headers) is still maintained but no longer developed.

## Add the relay route

Helicone takes no spans from the page, so there is no relay for it. Skip this step, or keep it when you also send spans to a backend: pick that backend in [Installation](/observability/installation) and follow its step 4.

## Observe the page

The same: the page's runs and tool calls are spans, which Helicone does not take. Skip it unless you send spans elsewhere.

## Check it in Helicone

Start the app and send one message in the chat. Each model call appears in Helicone. To group a conversation's calls into a Helicone session, the provider takes `extraBody: { helicone: { sessionId, userId } }` per model.

Six steps, from the packages to one trace per turn in W&B Weave: the same six on every backend's page. The framework
picker above the code picks your routes; the backend stays picked for the pages after this one.

<div class="install-steps">

## Install the packages

The telemetry layer and its OpenTelemetry packages, plus the protobuf exporter: Weave accepts OTLP as protobuf only.

```package-install
npm install @webmcp-agents/telemetry @opentelemetry/api @opentelemetry/sdk-trace @ai-sdk/otel @opentelemetry/exporter-trace-otlp-proto
```

## Add the server layer

Weave files traces by two resource attributes, `wandb.entity` and `wandb.project`, not by a header: set them here (or in `OTEL_RESOURCE_ATTRIBUTES=wandb.entity=my-team,wandb.project=field-store`). The layer also maps the key Weave groups threads by.

<include meta='title="lib/observability.ts"'>/_examples/observability/backends/weave.ts</include>

## Add the relay route

The page's spans come to your own endpoint, so the backend's key never reaches the browser. The relay refuses other origins and requests with no `Origin` (a script, not a page); the `guard` is the per-IP limit for the rest. Keep its counts in a shared store in production, as for the chat ([Limits and budgets](/security/limits)).

## Check it in W&B Weave

Start the app and send one message in the chat. The trace appears under the entity and project, grouped into a thread by `wandb.thread_id`. Weave maps both `gen_ai.*` and the AI SDK's `ai.*` attributes, so the default conventions work.

The run and its tool calls happen in the browser: the cursor moving, the person confirming, a call cancelled because
they scrolled away. Only the page can time those, so the page records them. `observeAgents()` (or `<ObserveAgents>`
in React) subscribes to the run events and turns them into spans.

## The relay

A backend's API key must never reach the page. So by default the page posts its spans to your own endpoint,
`/api/telemetry`, and the server forwards them through the same layer as its own spans:

<include meta='title="api/telemetry.ts"'>/_examples/vite/api/telemetry.ts</include>

The relay does not trust the page. It refuses cross-site requests, caps the body at 256 KB, accepts only OTLP JSON
from this library's instrumentation scope, redacts every attribute again, replaces the page's resource with the
server's, and lets the server's sampling decide. It answers `202` with no body and never reveals an upstream error.
Put it behind the same rate limits as the chat ([`createVercelTelemetryRoute`](/reference/vercel-api/create-vercel-telemetry-route)
does that on Vercel). A page whose relay answers `404` stops sending.

## What it costs the page

Up front, about 0.7 KB (min+gz): the subscription. The span builder, about 3.7 KB, loads when the first run the person
agreed to starts. A page where no agent runs, or where consent is never given, never downloads it. Spans are sent in
batches (every 2 seconds, or 64 spans), and what is still buffered is sent with `keepalive` when the page is hidden.

## A page that already runs OpenTelemetry

If the page registered an OpenTelemetry Web SDK provider (yours, or one from Sentry or Datadog RUM), the spans go to
that provider instead of the relay, and join the page's own traces. The bridge to it, and `@opentelemetry/api`, load
only on such a page. Pass `tracerProvider: "own"` to keep using the relay anyway.

## While you build

<include meta='title="observe.ts"'>/_examples/observability/console.ts</include>

`consoleExporter()` prints each span in the browser's console, redacted, and sends nothing. Any object with an
`export(spans)` method works as an exporter; [`SpanRecord`](/reference/telemetry/observe-agents#spanrecord) is what it
receives.

## On-device runs

A run on the on-device model has no server. Its model steps become `chat` spans built in the browser, without token
counts.

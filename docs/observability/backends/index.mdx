There is no vendor code in `@webmcp-agents/telemetry`: a backend is a recipe. Each page below is an environment block
or one constructor from the vendor's own package, the `conventions` value when the default does not fit, and the
`metadataMapping` that groups a conversation. Every value was checked on the vendor's docs on 2026-11-25, and each
page links its sources.

Only the generic OTLP path was run by us, against a local OpenTelemetry Collector. Each page says at the top whether
it was run.

| Backend | How | Protocol | Group a conversation by |
|---|---|---|---|
| [Any OTLP backend](/observability/backends/otlp) (Grafana, Honeycomb, SigNoz, Axiom, Jaeger, a Collector) | env | as the backend says | your backend's key |
| [Arize Phoenix and AX](/observability/backends/arize) | span processor | protobuf | `session.id` |
| [Braintrust](/observability/backends/braintrust) | span processor, or env | JSON | |
| [Datadog](/observability/backends/datadog) | env, or `dd-trace`'s provider | JSON or protobuf | `gen_ai.conversation.id` |
| [Helicone](/observability/backends/helicone) | a model provider, not telemetry | | |
| [IBM Instana](/observability/backends/instana) | env (agentless or host agent) | protobuf | |
| [Laminar](/observability/backends/laminar) | env | JSON or protobuf | `lmnr.association.properties.session_id` |
| [Langfuse](/observability/backends/langfuse) | span processor, or env | JSON or protobuf | `langfuse.session.id` |
| [LangSmith](/observability/backends/langsmith) | env | protobuf | `langsmith.trace.session_id` |
| [LangWatch](/observability/backends/langwatch) | exporter | protobuf (its exporter) | `langwatch.thread.id` |
| [New Relic](/observability/backends/new-relic) | env | protobuf | |
| [PostHog](/observability/backends/posthog) | env, or exporter | JSON or protobuf | `gen_ai.conversation.id` |
| [Sentry](/observability/backends/sentry) | Sentry's provider | | `gen_ai.conversation.id` |
| [Traceloop](/observability/backends/traceloop) | env | protobuf | `traceloop.association.properties.*` |
| [Vercel](/observability/backends/vercel) | Vercel's provider (`@vercel/otel`) | | |
| [W&B Weave](/observability/backends/weave) | env | protobuf only | `wandb.thread_id` |

"Protobuf" means install `@opentelemetry/exporter-trace-otlp-proto` and set `OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf`.
Where a vendor's docs do not say that OTLP JSON is accepted, the recipe sets protobuf rather than guess.

To send to more than one, use one [Collector](/observability/collector) that fans out.

## `conventions`

The model spans' attributes come in two styles: `gen_ai.*`, the OpenTelemetry GenAI conventions (the default,
`conventions: "genai"`), and the AI SDK's older `ai.*` spans (`"legacy"`), which some tools were built on. `"both"`
emits each set from its own tracer, so model steps appear twice: use it only to compare. Most backends above now read
`gen_ai.*`; the LangWatch recipe keeps `"legacy"`.

## `metadataMapping`

A backend groups a conversation's traces by a key of its own. `metadataMapping` copies `webmcp.conversation.id` to it.
The copy is exported as it is, never redacted ([why](/observability/privacy#metadatamapping-exports-the-target-raw)).

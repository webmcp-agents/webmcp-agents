## Set it up

Datadog's agentless intake takes OTLP over HTTP as JSON or protobuf (not gRPC), so the built-in exporter works with
only the environment:

<include meta='title=".env"'>/_examples/observability/env/datadog.env</include>

| Value | From Datadog's docs |
|---|---|
| Endpoint | `https://otlp.<site>/v1/traces`: `otlp.datadoghq.com`, `otlp.datadoghq.eu`, `otlp.us5.datadoghq.com`, `otlp.ddog-gov.com`. A `403` means the host does not match your site. |
| Headers | `dd-api-key: <key>`; `compute_stats=true` computes trace metrics, which the direct intake does not do by default. |
| LLM Observability | Only with the resource attribute `dd_llmobs_enabled=true` (or the header `DD-LLMObs-Enabled: true`). It reads `gen_ai.*` and drops spans without it. |
| A Datadog Agent | It receives OTLP on 4317 and 4318: point `OTEL_EXPORTER_OTLP_ENDPOINT` at it instead, and the Agent holds the key. |

Keep the default `conventions: "genai"`: LLM Observability maps the AI SDK's older `ai.*` spans only partly.

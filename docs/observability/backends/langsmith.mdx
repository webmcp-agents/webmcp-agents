## Set it up

LangSmith takes OTLP at `/otel` under its API host. Install `@opentelemetry/exporter-trace-otlp-proto` and set:

<include meta='title=".env"'>/_examples/observability/env/langsmith.env</include>

| Value | From LangSmith's docs |
|---|---|
| Endpoint | `https://api.smith.langchain.com/otel` (US). EU `https://eu.api.smith.langchain.com/otel`, APAC `apac.`, AWS `aws.`; self-hosted `https://<host>/api/v1/otel`. The exporter appends `/v1/traces`. |
| Auth | `x-api-key: <LANGSMITH_API_KEY>`. |
| Project | `Langsmith-Project: <name>` (the legacy form), or the newer `Langsmith-Agent-Id` with `Langsmith-Agent-Environment`, both or neither. Sending `Langsmith-Project` with the agent headers is refused with `400`. |
| Protocol | **Protobuf.** LangSmith's docs do not say whether OTLP JSON is accepted, and every example of theirs, their own JS exporter included, uses protobuf. We could not confirm JSON, so this recipe sets `http/protobuf`. |

The code is the [one line from the overview](/observability#a-complete-example).

| Value | From LangWatch's docs and package |
|---|---|
| Package | `langwatch`, export `LangWatchExporter` from `langwatch/observability` (an alias of `LangWatchTraceExporter`; it sends protobuf). Options `apiKey`, `endpoint`, `projectId`, `filters`. |
| Environment | `LANGWATCH_API_KEY`; `LANGWATCH_ENDPOINT` for a self-hosted instance (default `https://app.langwatch.ai`); `LANGWATCH_PROJECT_ID` for user-scoped keys. |
| Without the package | OTLP to `https://app.langwatch.ai/api/otel/v1/traces` with `Authorization: Bearer <LANGWATCH_API_KEY>`. JSON and protobuf are both accepted; gRPC is not. |

`conventions: "legacy"` sends the AI SDK's `ai.*` spans, which LangWatch's AI SDK integration is built on. Its docs do
not say whether plain `gen_ai.*` spans are read the same way; try the default if you prefer it.

The exporter drops HTTP request spans by default (`filters`); the agent's spans are not affected.

## Group a conversation

LangWatch groups messages into threads by `langwatch.thread.id` (and people by `langwatch.user.id`), as in the
example's `metadataMapping`.

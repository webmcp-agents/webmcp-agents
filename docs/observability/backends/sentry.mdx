**Not run by us against Sentry.** Written from Sentry's docs on 2026-11-25. We checked offline, with `@sentry/node`
11.17.0 and a placeholder DSN, that the layer finds Sentry's provider when the option below is set, and finds none
without it.

## Set it up

If your server already initializes Sentry, add one option. `enableOpenTelemetrySetup: true` makes Sentry register its
OpenTelemetry provider, which the chat's layer then finds and uses ([rule 3](/observability/where-spans-go)). Without
it, most of Sentry's server SDKs register none, and the layer stays off.

`@sentry/nextjs` and `@sentry/sveltekit` turn the option on by default. Sentry never replaces a provider that is
already registered: if your app has its own, follow Sentry's custom setup instead (its OTLP endpoint in your
provider), and the layer uses your provider.

Through Sentry's provider, the layer redacts the attributes it sets before each span exists; Sentry's own
instrumentations, such as its `vercelAIIntegration` (on by default when tracing is on, with its own `recordInputs` and
`recordOutputs`), are Sentry's to configure.

## Group a conversation

Sentry groups AI spans into conversations by `gen_ai.conversation.id`; the example maps the conversation id to it.
Set the person with `Sentry.setUser`.

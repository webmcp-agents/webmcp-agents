`appIntegrations` matters only when your app registered the AI SDK's OpenTelemetry integration itself
(`registerTelemetry(new OpenTelemetry())` from `@ai-sdk/otel`) and its spans go to the same provider as the layer's.
Both would then record every model step of the chat, so a backend would show each step twice. By default the layer
leaves the app's integration out of the chat's own calls, and says so once.

## Notes

<Accordion>
  <AccordionItem title="When the app's integration is always kept">
    Other integrations the app registered always run. So does the app's `@ai-sdk/otel` one on a request the layer does
    not sample, and whenever the layer builds its own provider (`exporters`, `spanProcessors`, or the environment
    alone).
  </AccordionItem>
  <AccordionItem title="An integration with another provider's tracer">
    An `@ai-sdk/otel` integration the app gave a tracer of another provider is left out as well. Pass `"keep"` then.
  </AccordionItem>
  <AccordionItem title="The app's integrations never record content">
    An integration the app registered still runs on each step but never records prompts or answers: it cannot redact,
    so only this layer's spans carry content ([Privacy and redaction](/observability/privacy)).
  </AccordionItem>
</Accordion>
